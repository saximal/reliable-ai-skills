# Contributing

Keep each skill focused on a recognizable task. Describe the inputs, decisions and observable outputs that improve an agent's work. Put conditional detail in linked references and keep the entry point easy to load.

Run the repository checks described in [validation](docs/VALIDATION.md). Use synthetic fixtures and loopback HTTP servers for tests. Explain any additional runtime dependencies. Preserve existing output receipts and check failure paths when changing a helper that writes artifacts.

For a behavioral correction, include the smallest example that demonstrates the issue and the expected result. For an instruction change, use a fresh evaluation task and record the actual outcome. Keep environment-specific assumptions visible.

Submit changes through a pull request with the affected skill, the reason for the change and the checks executed. Report sensitive findings privately through the repository owner's GitHub profile before sharing credentials or private data in an issue.
